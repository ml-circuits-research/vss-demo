# Publishing a preview build to the public repository

The one-file editor (`app/dist/vss-editor.html`) is published on demand to https://github.com/ml-circuits-research/vss-public-demo.
Its GitHub Pages site has an `index.html` that opens the LATEST build automatically (and lists every build with `?list`); every build
is kept under `builds/` with its source commit, in `builds/index.json` and in the README table. The workflow is
`.github/workflows/publish-preview.yml` here; nothing of the source leaves this repository, only the built file. Previews are no
longer committed under `builds/` in this repository.

## Why a key, and which key

The workflow runs inside this private repository and must be allowed to push one file into the public repository. GitHub does not
let a workflow write to another repository by default, so it needs a credential. The simplest one is a **deploy key**: an SSH key
pair made for exactly this. Its PUBLIC half is registered on the public repository with write permission (so that whoever holds the
private half may push there, and nowhere else); its PRIVATE half is stored as a secret in this repository, where only the workflow
can read it. You do not have to generate anything: the pair was generated by the coordinator session; the public half is printed
below, the private half was sent to you as the file `deploykey`.

## One-time setup (about five minutes)

1. Open https://github.com/ml-circuits-research/vss-public-demo/settings/keys and click **Add deploy key**. Title:
   `vss-demo publish-preview (write)`. Key: paste the line below. Tick **Allow write access**. Click Add deploy key.

   ```
   ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILGDfMVZvd6CZli/8mmn4gERjww5ALrg6fJ3CdW0iP1v vss-demo publish-preview deploy key
   ```

2. Open https://github.com/ml-circuits-research/vss-demo/settings/secrets/actions and click **New repository secret**. Name:
   `PUBLIC_DEMO_DEPLOY_KEY`. Secret: open the file `deploykey` you received in a text editor and paste its whole content (from
   `-----BEGIN OPENSSH PRIVATE KEY-----` to `-----END OPENSSH PRIVATE KEY-----`). Click Add secret. Then delete the file from
   your computer; it must never be committed.

3. Open https://github.com/ml-circuits-research/vss-public-demo/settings/pages: Source "Deploy from a branch", branch `main`,
   folder `/ (root)`, Save. (If Pages is already on with these settings, nothing to do.)

If you would rather make your own pair: on a computer with OpenSSH, `ssh-keygen -t ed25519 -N "" -f deploykey` gives
`deploykey.pub` (step 1) and `deploykey` (step 2).

## Publishing a build

Open https://github.com/ml-circuits-research/vss-demo/actions, choose **Publish preview build**, click **Run workflow**. Inputs:
`label` (optional, e.g. `probe-c`), `ref` (a commit, branch or tag of this repository; default the current branch), `latest`
(mark it as the build the site opens; default on). The run builds with `npm ci` and `node app/build/build.mjs`, names the file
`vss-editor-<date>-<sha>[-<label>].html`, pushes it to the public repository and updates `builds/index.json` and the README table.
The run's summary shows the file name; the site opens it at https://ml-circuits-research.github.io/vss-public-demo/ within a minute
or two (GitHub Pages rebuilds on every push).

How to build locally and what is in the file: `app/README.md`.
