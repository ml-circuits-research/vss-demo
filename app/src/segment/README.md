# app/src/segment: segmenter, SOP circuit, order, conflicts (spec 15)

| file | content |
|---|---|
| `segment.js` | `segment(tokens, {reader})`: candidate cuts (sentence punctuation; connectives: and, then, and then, also, because, so, but, after that, before that, if, when, unless, says that; commas), strong where the reader's gate is open after a connective (`reader.gates`, when the model exposes level openers) or, without gates, where a command starts after it by the kinds (a VERB after FILLER / negation words); weak otherwise. Every unit is read by the injected reader; a poor unit (status no-sense / abstain / unknown-event, a core role empty, a residual above `maxResidual`) is merged with a neighbour or split at a weak cut and read again, hill-climbing by the stated rule: fewer tokens in poor units, then the highest minimum margin, then the smallest total residual, then fewer units. A tie between two clear segmentations returns `ambiguous` and the second one in `alternatives` (shown as two readings). `readerAdapter(vss)` wraps `src/vss.js`. |
| `circuit.js` | `buildCircuit(units, opts)`: one SOP file with the four link kinds and their sources (reference / reader; shared entity / rule:recent, rule:label, rule:description, rule:section, rule:ordinal, rule:forward, rule:scene, user; discourse / rule:connective, as operator wires then, but, so, because, if, unless (if with a not), says; order / `_sentence=`); `_link.<role>=<source>` on every unit that refers across units; the execution order (Kahn, ties by text order) over introduction -> use, earlier use -> delete, then / but / so / if edges; a cycle report; conflicts by a port of the verdict of `tool/sop/diff.py` (`flattenFrame`, `verdict`, `diffFrames`); question wires (`_mood=question`) answered from the diagram. `executeCircuit(scene, circuit, opts)`: the paragraph as one plan and one undo entry, with the circuit's bindings (a description the diagram would resolve differently is bound to the linked components), conflicts put to the user before anything runs (`choices`), and a stop at the first unit that cannot run (`unread`, `blocking`: "stop" or "skip"). |
| `view.js` | `renderCircuit(container, circuit, ctx)`: the circuit view for the side panel (units as boxes in text order numbered in execution order, shared entities as pills, discourse arrows with their operator; cycle and conflicts listed); SVG in a scrollable container, phone width. |

The legend of the diagram world has `not` as its only operator; `then`, `but`, `so`, `because` are written by the circuit and must be
added to `tool/sop/legend.py` OPERATOR_KEYS (then/but: after, scope; so: cause, scope; because: scope, cause) for `sop check` to validate
a circuit file (the SOP Lang syntax is already valid: every circuit of the evaluation set parses and round-trips in `tool/sop/soplang.py`).

## Tests and what their numbers mean

`node app/tests/segment.mjs` (exit 0 on pass) runs on `training/data/diagram/eval/paragraphs.jsonl` (400 paragraphs and 200 long sentences
of 10 to 40 words, generated by `training/worlds/diagram/paragraphs.py` with their gold segmentation and gold circuit) with a FAKE reader
that returns the gold frame of each unit text, a NOISY fake, and hand-written cases (the specification's example, because / so /
unless / says that, gates, two readings, conflicts certain and uncertain, a question, a cycle, a forward reference, a user link, a
component already on the diagram, the diff port).

With the fake reader the cut accuracy, link precision and recall, execution order, cycles and conflicts are all 1.000: this checks the
code against an independent implementation of the same rules (the generator's gold), not the reader. These numbers become meaningful
only with the trained reader: `node app/tests/segment.mjs --model app/model/diagram` reports the cut accuracy (criterion >= 0.97), FULL
per unit by kind and length against the same units read alone (criterion: within 0.03), link precision and recall, and the execution
order on the scripted paragraphs (criterion: 100%). The noisy fake's numbers measure only how the rules degrade under a stated noise
model, never the reader.

Stated choices: the cut accuracy is boundary agreement, shared cuts over the union of predicted and gold cuts (with the share of
exactly segmented inputs beside it); a plain "and", "also" or a period adds no operator wire (the order of the text is the link);
"because" adds no execution edge (an explanation does not order execution); a prohibition stored as a lock keeps a lasting description
(the component's label, else its kind word), because the planner checks locks by description.
